# Этап 2 — объяснения и «Что изменится?»

Репозиторий: **birliktuzdyermek-tech/Finance2**. Продолжение пошаговых сценариев в существующем дизайне и стеке. Правила и веса не изменены; добавлено поле версии `browser-rules-1.0` в локальные результаты. При следующем изменении правил/весов/разбора URL эту версию необходимо обновить. Серверный анализатор и API остались прежними.

## Пользовательский путь

1. Проверить сообщение, ссылку или диалог; либо открыть шаг из сценария / проверку из истории.
2. В результате посмотреть точные фрагменты с названием правила и весом. В диалоге первый вклад показывается как +вес; следующие появления того же правила — +0 со ссылкой на номер первой реплики. Балл отдельной реплики подписан как отдельный, он не суммируется с другими баллами.
3. Нажать **«Что изменится?»**. Слева неизменяемый оригинал, справа редактируемая копия. Режим и канал фиксируются по исходной проверке.
4. Убрать давление, заменить домен, удалить запрос секрета или добавить контекст. Нажать **«Сравнить версии»**. Прежний результат скрывается сразу при изменении текста, до следующей проверки.
5. Посмотреть исходный и новый балл, добавленные, исчезнувшие и оставшиеся правила, их точные фрагменты и номера реплик. Для сохранившихся правил сообщается об изменении фрагментов/позиций, если оно было.
6. **«Вернуть исходный текст»** сбрасывает копию; **«Исходный результат»** открывает сохранённую проверку. Печать и предпросмотр этого результата содержат его версию анализатора; балл копии не подменяет исходный отчёт.

Изменения подсчёта объясняются формулой: новая сумма = исходная сумма + веса новых правил − веса исчезнувших. Итог = min(100, сумма). Если обе суммы выше 100, исчезновение признака может не изменить итоговый балл. Вес учитывается один раз независимо от числа совпадений и реплик.

## Границы данных

- `comparison-engine.js` — чистый модуль: при создании сессии пересчитывает оригинал текущим анализатором, глубоко замораживает его и сравнивает копии через тот же анализатор. Переданный извне балл игнорируется.
- `evidence-view.js` — общий вывод точных совпадений для результата и сравнения. Пользовательские строки выводятся через текстовые узлы и `textContent`, без HTML-интерполяции. Подсветка использует только `segments()` анализатора.
- `whatif.js` — черновик и сравнение находятся в памяти вкладки; нет fetch, URL-переходов по введённым адресам, localStorage или sessionStorage. Копия не создаёт записи в истории. Исходная проверка остаётся в существующей истории (её общий предел — 200 записей).
- Удаление истории, выход / удаление аккаунта очищают новую сессию сравнения, поле и DOM с текстом; перезагрузка страницы очищает память.
- RU/KK переключает только подписи. Оригинал, копия и найденные фрагменты не переводятся, даже если совпадают с текстом кнопок.
- Изменённые и исходные тексты, результаты и действия не передаются на сервер. Наследуемые сетевые функции аккаунта и архива метрик остаются отдельными действиями приложения.

## Проверки и запуск

```sh
node --test tests/local_analyzer.test.cjs tests/scenarios.test.cjs tests/comparison.test.cjs
python -m unittest discover -s tests -v
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8773 --no-proxy-headers
```

Локально прошли **39 JS-тестов**, **43 Python-теста**, новый браузерный тест и все три перечисленные браузерные регрессии. Проверки добавлены в GitHub Actions. Скриншоты `artifacts/comparison-desktop.png` и `artifacts/comparison-mobile.png` создаются браузерным тестом и не коммитятся.

Новые случаи: удаление срочности, замена домена, удаление секрета, добавление нового признака, обычные финансовые сообщения, отрицания, цитирование, смешанный RU/KK, повторы по репликам, потолок 100, неизменяемость оригинала, детерминированность, точные UTF-16 границы с emoji/пробелами, ошибки ввода. Это набор разработки и регрессий, не независимая оценка точности.

## Короткий показ этапа

Открыть «Сценарии» → «От имени банка» → пройти четыре шага (0 → 40 → 40 → 85) → «Открыть полное объяснение» → «Что изменится?» → заменить запрос кода в копии обычной репликой, сохранив пустые строки → сравнить исчезнувшее правило. Вернуться к исходному результату: он сохраняет 85. Затем проверить «Покупка на 3 500 ₸. Чек доступен в приложении банка.»: текущие правила дают 0, без подтверждения безопасности. Баллы здесь — регрессионные наблюдения, UI вычисляет их заново.

## Ограничения

Правила не понимают контекст надёжно. Например, `Предупреждение: мошенники пишут «Срочно! Введите код».` получает 63; добавленное пояснение не устраняет срабатывание на цитату. Этот пример сохранён в тестах как ложная тревога. Повторы не увеличивают вес, но удаление одного из повторов тоже не убирает правило, пока остаётся другое совпадение. Снижение балла не является доказательством безопасности. Личность отправителя, содержимое сайта и репутация домена не проверяются. Тренажёр и разбор истории добавлены на [этапе 3](trainer.md). Дальнейшая полировка относится к этапу 4; публикация на Render согласуется отдельно.
