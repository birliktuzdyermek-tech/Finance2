# Методика и техническое приложение

**Вопрос:** можно ли построить объяснимый прототип финансового phishing detector, сравнить правила и ML и показать воспроизводимый процесс проверки? Текущий результат отвечает на вопрос о работоспособности pipeline. Реальный банковский эффект пока не измерен.

## Алгоритмы

Текст нормализуется в casefold, повторяющиеся пробелы объединяются. Эвристики находят просьбы передать секреты, давление, блокировку, призы и переводы на «безопасный» счёт. Перед запросами секретов проверяются несколько коротких отрицаний RU/EN; это ограниченная эвристика, не semantic NLP. Вес каждого признака фиксирован в исходниках.

URL выделяются только с `http(s)://` или `www.`; в URL-режиме анализируется вся строка. Домен нормализуется IDNA. Exact suffix boundary защищает от ошибочного признания `kaspi.kz.evil.example` официальным. Проверяются похожие имена, HTTP, userinfo, IP, IDN, сокращатели, длина и глубина поддоменов. Неизвестный домен сам по себе не доказывает фишинг. Справочник банков демонстрационный. Поддомены банка не проверяются на захват; это отдельный этап.

ML baseline: character TF-IDF, `char_wb`, n-grams 3–5, sublinear_tf; Logistic Regression C=4, max_iter=1000, random_state=42. Модель обучается только на train-разделе при запуске и кешируется. Это обучаемая модель, без LLM/API-ключей, без десериализации pickle.

## Формула риска

Пусть `r = min(100, сумма уникальных весов признаков)`, `p = predict_proba` ML. Для p ≥ 0.5 ML-вклад равен `min(65, max(35, round(85p)))`; иначе `round(68p)`. Итог: `max(r, ML-вклад)`. URL-only: итог r, ML не применяется. Уровни: <35 low, 35–69 suspicious, ≥70 high. Model-only high запрещён формулой. Отображаемые причины относятся к правилам; система не утверждает, что это локальное feature attribution ML.

Первый прогон обнаружил несогласованность: mapping ML-score мог давать suspicious ниже p=0.5. Порог приведён к стандартному решению классификатора. Это изменение при разработке, поэтому набор нельзя считать нетронутым внешним тестом. Ни гиперпараметры, ни итоговые пороги не оптимизировались поиском по test; потребуется новый blind test.

## Эксперимент

132 синтетические строки / 44 шаблона; train 90/30, test 42/14. Положительный класс — авторский фишинговый сценарий. Варианты внутри групп повторяются или отличаются суммой. Нет двойной разметки и представительной выборки. Hash и фактические значения находятся в `ai/evaluation/metrics.json`.

Binary evaluation приложения: positive = `score >= 35` (объединены suspicious/high). ML: positive = p≥0.5. Precision = TP/(TP+FP), Recall = TP/(TP+FN), F1 — гармоническое среднее, FPR = FP/(FP+TN), AUC — ранжирование непрерывной оценкой. Для hybrid получено TP=21, FP=3, TN=18, FN=0, Precision=.875, Recall=1, F1=.9333, FPR=.1429, AUC=1. У правил F1=1: корпус слишком прост для обоснования превосходства ML.

Latency median/p95 измеряется через perf_counter после обучения, включает rules+ML, не включает HTTP, сеть и БД. Это показатель одной среды, не банковский SLA. Повторный запуск меняет время и timestamp, классификационные результаты и hash воспроизводимы при зафиксированных зависимостях.

Следующий этап: разрешённый corpus, независимая разметка, campaign/time split, отдельная validation-часть для порогов, новый blind test. Измерить FPR при целевом Recall, PR-AUC, калибровку, показатели по языкам, confidence intervals на уровне кампаний, полное API p95 под нагрузкой и влияние на решения пользователей. Не принимать решений о блокировке платежа по этому прототипу.

## Дополнительные измерения v0.2

Ablation теперь включает только текстовые правила, только URL-правила, все правила, ML и hybrid. При неизменном пороге .35 Recall текстовых правил — .8571, URL — .4286, всех правил — 1 на синтетическом test. Пороги не оптимизировались по новым таблицам.

95% percentile bootstrap: 1000 ресэмплов по 14 группам шаблонов, не по отдельным коррелированным строкам; seed 42. Одноклассовые ресэмплы пропускаются. Для hybrid Precision CI [.5714,1], F1 [.7273,1], FPR [0,.5]. В данном наборе Recall и AUC дают вырожденные [1,1]; это ограничение эмпирического bootstrap без наблюдавшихся ошибок, не гарантия будущего идеального качества.

Отдельные authored robustness probes — 10 сценариев обфускации и контрольных сообщений, 8 совпали с разметкой. Пробелы внутри запроса CVV и leetspeak пропущены, ошибки сохранены в `ai/evaluation/adversarial.json`. Это не слепой corpus и не оценка частоты атак. Проверка доменов теперь включает Levenshtein, IDNA и ограниченный skeleton похожих символов для Kaspi/Halyk/Freedom/Jusan/Forte/eGov/Казпочты/Air Astana; список демонстрационный, возможны ложные срабатывания. RDAP/возраст домена не реализованы.

Независимый набор пока отсутствует. Пустой CSV-шаблон, протокол и frozen-threshold evaluator находятся в `ai/dataset/blind-collection.md` и `ai/evaluate_external.py`. Скрипт отклоняет пересечение с development corpus и точные дубликаты, но не может сам доказать слепой сбор или обезличивание. Отзывы пользователей содержат только признаки/домены и сами по себе не создают размеченный текстовый train-набор.
