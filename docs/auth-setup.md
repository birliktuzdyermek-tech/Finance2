# SMS + email регистрация: Twilio и Resend

Реализован passwordless вход с двумя независимыми шестизначными кодами. Их принимают только вместе, в браузере, запросившем коды. TTL — 10 минут, максимум 5 попыток; новая отправка ограничена 3 запросами в час на peer, телефон и почту. Контакты сохраняются с согласием, код — только в виде HMAC. После входа cookie заменяется, текущая история переносится в аккаунт. На другом устройстве нужно подтвердить ту же пару контактов. Выход отзывает сеанс; удаление аккаунта удаляет контакты, историю, отзывы и все сеансы.

На Render регистрация требует **PostgreSQL**: временный SQLite не подходит для аккаунтов. При отсутствии базы/провайдеров API возвращает 503, а интерфейс отключает отправку кодов. Фиктивные коды или development bypass публично не выдаются.

## Если аккаунтов пока нет

1. Зарегистрируйтесь в [Twilio](https://www.twilio.com/try-twilio), подтвердите свою почту и телефон. Выберите SMS / Programmable Messaging. Наша интеграция использует Messaging API и собственные коды, а не отдельный продукт Twilio Verify.
2. Проверьте условия именно вашего аккаунта: текущие [Twilio Trial](https://www.twilio.com/docs/usage/trials) допускают только подтверждённых получателей и заранее заданные шаблоны. Для собственных текстов OTP может потребоваться Upgrade. Legacy trial может иметь другие условия. Покупку номера и оплату выполняет владелец аккаунта после проверки доступности отправки в Казахстан; ключи сами по себе не снимают ограничения trial.
3. В Twilio Console найдите Account SID и Auth Token. Настройте SMS-отправителя: номер с SMS capability или Messaging Service с подключённым отправителем. В **Messaging → Settings → Geo Permissions** проверьте разрешение Казахстана. Отправитель должен поддерживать это направление: [географические настройки](https://www.twilio.com/docs/messaging/guides/sms-geo-permissions), [условия SMS для Казахстана](https://www.twilio.com/en-us/guidelines/kz/sms). `TWILIO_FROM_NUMBER` — отправитель Twilio, а не ваш личный телефон.
4. Зарегистрируйтесь в [Resend](https://resend.com/signup), подтвердите почту. В API Keys создайте ключ с правом **Sending access**; после настройки домена можно ограничить ключ этим доменом.
5. Для писем всем пользователям нужен собственный домен с доступом к DNS. Адрес приложения `qalqan-finance2.onrender.com` не является вашим почтовым доменом. В [Resend Domains](https://resend.com/domains) добавьте свой домен или поддомен, перенесите выданные Resend DNS-записи в панель регистратора и дождитесь **Verified**. Значения DNS берите из своего аккаунта: [официальная инструкция](https://resend.com/docs/dashboard/domains/introduction). Затем задайте `AUTH_EMAIL_FROM`, например `Qalqan <login@your-domain.kz>`.
6. Пока домена нет, для ограниченного теста можно использовать `AUTH_EMAIL_FROM=Qalqan <onboarding@resend.dev>` и только почту, на которую зарегистрирован Resend. Для других адресатов нужен подтверждённый домен: [ограничение resend.dev](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain). Эта настройка не означает, что регистрация открыта всем.
7. Добавьте настройки из таблицы ниже в Render, подключите PostgreSQL и выполните Save and deploy. Покупка домена не нужна для проверки интерфейса; она понадобится для реальной почтовой регистрации произвольных пользователей через Resend.

Не отправляйте в чат Auth Token, API key, строку подключения базы или полученные коды. Для помощи достаточно сообщить, какой этап выполнен, статус домена и обезличенный код ошибки провайдера.

## Настройка существующего сервиса

Откройте [Environment qalqan-finance2](https://dashboard.render.com/web/srv-db1igdqd0e5s73ftf730/env). Секреты добавляйте туда, а не в GitHub или чат.

| Ключ | Откуда взять |
|---|---|
| `DATABASE_URL` | Internal Database URL [созданной PostgreSQL](https://dashboard.render.com/d/dpg-db1i92ou01pc73eit61g-a) |
| `AUTH_SECRET` | Стабильный случайный секрет минимум 32 символа; при первичной настройке генерируется для сервиса |
| `TWILIO_ACCOUNT_SID` | [Twilio Console](https://console.twilio.com/) |
| `TWILIO_AUTH_TOKEN` | Twilio Console; хранить как секрет |
| `TWILIO_MESSAGING_SERVICE_SID` | SMS Messaging Service; либо вместо него задайте `TWILIO_FROM_NUMBER` — отправителя Twilio в E.164 |
| `RESEND_API_KEY` | [Resend API keys](https://resend.com/api-keys) |
| `AUTH_EMAIL_FROM` | Например, `Qalqan <login@your-verified-domain.kz>` с вашим подтверждённым доменом Resend |

После подключения базы задайте `REQUIRE_POSTGRES=true` и выберите Save and deploy. `AUTH_SECRET` одинаков для всех реплик; не заменяйте его при каждом деплое. Изменение секрета делает действующие OTP непригодными.

Twilio trial ограничивает получателей; в текущем trial также ограничены собственные тексты SMS (см. инструкцию выше). Проверяйте SMS-capabilities отправителя, доступность направления Казахстана и действующие тарифы. Resend требует подтверждённый sender domain для регистрации произвольных пользователей; тестовый sender ограничен разрешёнными адресатами. Ответы провайдеров подтверждают принятие отправки, а не фактическую доставку получателю. Если один провайдер отклонил отправку, challenge отменяется; первый код всё же может прийти и будет непригоден для регистрации.

## Проверка после подключения

`GET /api/health`: `storage=postgresql`. `GET /api/auth/me`: `delivery_available=true`. Затем в `/#account` укажите собственные контакты, отметьте согласие и запросите коды. Оба контакта должны получить разные коды; подтвердите их и проверьте историю на другом устройстве. Не присылайте коды в чат. Настоящая доставка пока не проверена без ключей и подтверждённых контактов.

Автотесты используют mock только на границе доставки: остальная логика выполняется реально. `python -m unittest discover -s tests -v`; отдельная мобильная браузерная проверка — `CHROMIUM_PATH=/usr/bin/chromium python -m tests.auth_browser_smoke`. Этот тест не отправляет SMS или email.

До публичного банковского пилота подтвердите доверенные proxy, настройте клиентский IP и защиту платной отправки от abuse, согласуйте локализацию данных и договоры обработки. Текущий peer может быть адресом Render proxy; квота отправки тогда общая для нескольких клиентов. Не доверяйте произвольному X-Forwarded-For. Контакты на Render Frankfurt нельзя объявлять соответствующими локализации РК без проверки. Справочная нормативная база: [Закон РК «О персональных данных и их защите»](https://adilet.zan.kz/rus/docs/Z1300000094).
