# Регистрация по почте через Resend

Вход и регистрация используют один шестизначный код из письма. Телефон не запрашивается, SMS не отправляются, Twilio не нужен. Код принимается только в браузере, запросившем его. TTL — 10 минут, максимум 5 попыток; отправка ограничена 3 запросами в час на peer и почту. Адрес сохраняется с согласием; код — только в виде HMAC. После входа cookie заменяется, а текущая история переносится в аккаунт. На другом устройстве подтвердите ту же почту. Выход отзывает сеанс; удаление аккаунта удаляет адрес, историю, отзывы, сеансы и ожидающие коды.

На Render регистрация требует **PostgreSQL**: временный SQLite не подходит для аккаунтов. При отсутствии базы или настройки Resend API возвращает 503, интерфейс отключает отправку. Фиктивные коды публично не выдаются.

## Настройка с нуля

1. Создайте аккаунт [Resend](https://resend.com/signup) и подтвердите свою почту.
2. Откройте [API Keys](https://resend.com/api-keys), создайте ключ с правом **Sending access**. Сохраните ключ непосредственно в Render как `RESEND_API_KEY`; не отправляйте его в чат и не добавляйте в GitHub.
3. Пока собственного домена нет, для проверки используйте `AUTH_EMAIL_FROM=Qalqan <onboarding@resend.dev>`. Письмо можно отправить только на почту владельца аккаунта Resend. Это ограниченный тест, а не регистрация для всех: [официальное ограничение](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain).
4. Для регистрации других пользователей добавьте свой домен или поддомен в [Resend Domains](https://resend.com/domains). Укажите выданные Resend DNS-записи в панели регистратора, дождитесь **Verified**, затем задайте отправителя, например `Qalqan <login@your-domain.kz>`. Адрес сайта `qalqan-finance2.onrender.com` не является вашим почтовым доменом. [Инструкция по домену](https://resend.com/docs/dashboard/domains/introduction).
5. Подключите PostgreSQL и сохраните настройки ниже в [Environment qalqan-finance2](https://dashboard.render.com/web/srv-db1igdqd0e5s73ftf730/env), выбрав Save and deploy.

Бесплатный тариф Resend имеет дневной и месячный лимиты, актуальные условия: [Pricing](https://resend.com/pricing). Стоимость собственного домена, если его ещё нет, оплачивается отдельно регистратору.

| Ключ | Значение |
|---|---|
| `DATABASE_URL` | Internal Database URL [созданной PostgreSQL](https://dashboard.render.com/d/dpg-db1i92ou01pc73eit61g-a) |
| `AUTH_SECRET` | Уже создан в существующем сервисе; стабильный случайный секрет минимум 32 символа |
| `RESEND_API_KEY` | Ваш ключ с Sending access из Resend |
| `AUTH_EMAIL_FROM` | Тест: `Qalqan <onboarding@resend.dev>`; публичная регистрация: адрес вашего подтверждённого домена |
| `REQUIRE_POSTGRES` | `true` после подключения базы |

`AUTH_SECRET` должен быть одинаковым у реплик; не заменяйте его при каждом деплое. Настройки Twilio приложению больше не нужны.

## Проверка

`GET /api/health`: `storage=postgresql`. `GET /api/auth/me`: `delivery_available=true`. Затем откройте `/#account`, укажите собственную почту, отметьте согласие и запросите код. Проверьте вход, выход и доступ к истории с другого устройства. Код вводите на сайте, не в чате.

HTTP-успех Resend означает принятие запроса, а не подтверждение доставки в почтовый ящик. Для диагностики смотрите статус в Resend Emails и папку «Спам». Если провайдер отклоняет запрос, challenge отменяется; API возвращает безопасное сообщение без контактов, ключей и тела ошибки провайдера. Автотесты заменяют только доставку; реальные письма ими не отправляются.

## Обновление со старой схемы

При старте выполняется транзакционная миграция: ранее сохранённые номера удаляются из активных таблиц `users` и `auth_challenges`; ID аккаунтов, почта, сеансы и история сохраняются. Старые двухкодовые запросы отменяются: нужно запросить новый код на почту. Миграция повторяемая. Это удаление из активной базы не является заявлением об удалении старых резервных копий у оператора хостинга.

До публичного банковского пилота проверьте доверенные proxy и клиентский IP, защиту от злоупотребления отправкой, локализацию и договоры обработки. Peer может быть адресом Render proxy; тогда квота общая для нескольких клиентов. Не доверяйте произвольному X-Forwarded-For. Размещение почтовых адресов на Render Frankfurt требует проверки применимых требований РК; наличие согласия не доказывает соответствие. [Закон РК «О персональных данных и их защите»](https://adilet.zan.kz/rus/docs/Z1300000094).
