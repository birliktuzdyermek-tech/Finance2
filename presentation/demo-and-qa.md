## Сценарий видео, около 3:30

Начальная страница для живой защиты: https://qalqan-finance2.onrender.com/#demo. На ней собраны три синтетических сценария. Кнопка «Проверить пример» запускает локальные браузерные правила; обзор и история используют результаты в памяти вкладки. Метрики в архиве описывают отдельный серверный ML-эксперимент, а не эти три примера и не качество текущего браузерного анализатора. Страница сама не запускает проверки и не очищает существующую историю.

При сбое сервиса использовать заранее записанное видео и объяснить, что это запись. Скриншоты не заменяют видео. Рабочий URL: https://qalqan-finance2.onrender.com. Короткая запись без озвучки генерируется командой `CHROMIUM_PATH=/usr/bin/chromium python presentation/record_demo.py`, результат — `artifacts/Qalqan-demo.webm`.

## Краткие ответы

- **Где AI?** Обучаемая character TF-IDF + Logistic Regression есть в отдельном серверном API и эксперименте. Текущая форма проверяет сообщения локальными правилами в браузере и не показывает ML-оценку.
- **Почему правила лучше?** Синтетический набор слишком прост и похож на сценарии правил. Это ограничение эксперимента, требующее нового внешнего теста.
- **Почему в архиве Recall 100%?** Это серверный гибрид на 21 синтетическом положительном примере. У текущих браузерных правил Recall 85,7%: три русскоязычных примера пропущены. Ни одно значение нельзя переносить на реальный поток.
- **Что означают 87/100?** Индекс риска, не 87% вероятности. Калибровка не выполнена.
- **Какая новизна?** Продуктовая комбинация финансовых признаков, объяснения, RU/KZ/EN и воспроизводимого evaluation. Глобальный приоритет не заявлен.
- **Проверяется ли возраст домена?** Нет. Текущая URL-проверка offline; WHOIS/репутация предусмотрены следующим этапом.
- **Где данные пользователя?** В текущей веб-форме текст, история и результаты находятся в памяти вкладки и исчезают после перезагрузки; сохранённый пользователем PDF остаётся у него. Прямой вызов старого серверного API передаёт текст серверу, а БД хранит производные признаки и домены. Домены тоже могут быть чувствительными.
- **Есть ли банковские партнёры?** Не подтверждены. Текущий статус — лабораторный MVP.
- **Как измерить эффект?** Независимый corpus, FPR при заданном Recall, показатели по языкам, затем разрешённое исследование решений пользователей до/после.
- **Можно ли блокировать перевод?** На текущей модели нельзя обосновать автоматическую блокировку; рекомендуем проверку человеком.
- **Как масштабировать?** Общий limiter, SSO/роли, pool БД, реестр модели, monitoring и контролируемая интеграция; не добавлять реплики к process-local limiter.
- **Почему frontend без React?** Для MVP достаточно браузерного клиента без CDN и сборки; API остаётся независимым, переход на React возможен по мере развития продукта.
- **Есть ли гарантированная безопасность?** Нет, короткий текст, обфускация, неизвестные кампании и сложные отрицания могут приводить к ошибкам. Ограничения отображены в интерфейсе.

## Перед подачей

Уточнить официальное написание вуза, роли участников, руководителя и контакты; сверить оригинальный DOCX и допуск после 1 октября; добавить URL/видео; уточнить правила лицензии, формат технического приложения и официальную оценку TRL. Эти поля не заполняются вымышленными данными.
