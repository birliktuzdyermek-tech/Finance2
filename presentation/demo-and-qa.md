## Сценарий видео, около 3:30

Начальная страница для живой защиты: https://qalqan-finance2.onrender.com/#demo. На ней собраны три синтетических сценария. Кнопка «Проверить пример» открывает анализатор и выполняет настоящий API-запрос; обзор и история используют результаты текущей сессии. Метрики описывают отдельный тестовый набор, а не эти три примера. Страница сама не запускает проверки и не очищает существующую историю.

Перед записью очистить историю, использовать только демо-сообщения, закрыть личные вкладки, проверить PDF. Не показывать реальные PIN/коды. При сбое сервиса использовать заранее записанное видео и объяснить, что это запись. Скриншоты не заменяют видео. Рабочий URL: https://qalqan-finance2.onrender.com. Короткая запись без озвучки генерируется командой `CHROMIUM_PATH=/usr/bin/chromium python presentation/record_demo.py`, результат — `artifacts/Qalqan-demo.webm`.

## Краткие ответы

- **Где AI?** Обучаемая character TF-IDF + Logistic Regression, обучение из train CSV, вероятностный выход показан отдельно; итог объединяет его с правилами.
- **Почему правила лучше?** Синтетический набор слишком прост и похож на сценарии правил. Это ограничение эксперимента, требующее нового внешнего теста.
- **Почему Recall 100%?** В test только 21 положительная строка из семи шаблонов. Значение нельзя переносить на реальный поток; корреляция вариантов ещё уменьшает информативность.
- **Что означают 87/100?** Индекс риска, не 87% вероятности. Калибровка не выполнена.
- **Какая новизна?** Продуктовая комбинация финансовых признаков, объяснения, RU/KZ/EN и воспроизводимого evaluation. Глобальный приоритет не заявлен.
- **Проверяется ли возраст домена?** Нет. Текущая URL-проверка offline; WHOIS/репутация предусмотрены следующим этапом.
- **Где данные пользователя?** Исходный текст — в памяти запроса; БД хранит признаки и домены, история изолирована cookie. Домены также могут быть чувствительными. Удаление по сроку сейчас запускается новой проверкой.
- **Есть ли банковские партнёры?** Не подтверждены. Текущий статус — лабораторный MVP.
- **Как измерить эффект?** Независимый corpus, FPR при заданном Recall, показатели по языкам, затем разрешённое исследование решений пользователей до/после.
- **Можно ли блокировать перевод?** На текущей модели нельзя обосновать автоматическую блокировку; рекомендуем проверку человеком.
- **Как масштабировать?** Общий limiter, SSO/роли, pool БД, реестр модели, monitoring и контролируемая интеграция; не добавлять реплики к process-local limiter.
- **Почему frontend без React?** Для MVP достаточно браузерного клиента без CDN и сборки; API остаётся независимым, переход на React возможен по мере развития продукта.
- **Есть ли гарантированная безопасность?** Нет, короткий текст, обфускация, неизвестные кампании и сложные отрицания могут приводить к ошибкам. Ограничения отображены в интерфейсе.
