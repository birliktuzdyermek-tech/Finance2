# Qalqan Finance Security

Браузерный помощник Qalqan: точная подсветка признаков, анализ одного сообщения или диалога и четыре ситуации «Что уже произошло?». Основной интерфейс и рекомендации доступны на русском и казахском; правила поддерживают смешанные сообщения.

**Проверки выполняются локально.** Текст, URL, результаты, отзывы и выбранные действия не отправляются на сервер. История и обзор (до 200 результатов) хранятся в памяти вкладки до перезагрузки. Пакетная проверка, сравнение, CSV, проверка бренда, предпросмотр отчёта и режим проектора сохранены в опубликованном тёмном дизайне. PDF сохраняется через печать браузера.

Диалог: 2–20 реплик через пустую строку, до 10 000 символов. Общий балл складывает веса разных правил; повторы не увеличивают его. Балл **не является вероятностью**. Qalqan не подтверждает подлинность отправителя или сайта. [Описание и ограничения](docs/local-assistant.md).

Аккаунты и старые API сохранены для совместимости; новые проверки не синхронизируются с аккаунтом. Вход по почте остаётся отдельной сетевой операцией по действию пользователя. Разделы архива/презентации загружают фиксированные метрики прежнего серверного эксперимента, которые не описывают качество локальной проверки.

## Дизайн и навигация

- Тёмный адаптивный интерфейс с фоном `#0A1020`, голубыми акцентами, верхней навигацией и меню для телефона.
- Главная, анализатор и отдельный экран результата с выделением признаков в сообщении. Исходное сообщение остаётся только в памяти текущей страницы; при открытии результата из локальной истории доступна точная подсветка.
- [Проверка бренда](https://qalqan-finance2.onrender.com/#brand) и [типы схем](https://qalqan-finance2.onrender.com/#schemes): сравнение домена и объяснение предполагаемого сценария мошенничества.

- Предпросмотр отчёта и локальная печать/PDF. При печати результата исходный проверенный текст включается в файл. Серверный PDF endpoint сохранён для старых API-клиентов.
- [Презентация](https://qalqan-finance2.onrender.com/#presentation) содержит два экрана для защиты: процесс анализа и честные результаты синтетического эксперимента. Режим проектора доступен для результата и презентации.
- [Telegram](https://qalqan-finance2.onrender.com/#telegram) показан как концепт будущего канала. Работающий бот пока не подключён.

## Архив серверного обновления v0.2

Ниже описан сохранённый серверный путь. Текущий интерфейс анализа его не вызывает.

- Пакетный анализ до 10 сообщений/ссылок с атомарным сохранением и PDF для каждой записи.
- Поиск по домену/признаку/ID, фильтры источника/риска, сортировка, страницы по 20 результатов, CSV и сравнение двух проверок.
- Мобильное меню и вставка сообщения из буфера по нажатию. Пользователь может скопировать SMS/сообщение мессенджера и отправить на проверку в браузере.
- Аккаунты с подтверждением почты через Resend; телефон и SMS не нужны. HMAC OTP, 10 минут, 5 попыток, ограничение отправок, ротация cookie и история между устройствами. В публичном Render PostgreSQL подключена, ключи Resend настроены и API сообщает `delivery_available=true`. Автоматическая проверка входа подменяет только отправку письма; реальные письма агент не отправлял. Для собственного развёртывания — [настройка](docs/auth-setup.md). На Render без PostgreSQL регистрация отключена.
- Levenshtein, IDNA и ограниченные гомоглифы для казахстанских брендов; предполагаемые типы схем, пошаговые действия, отзыв только с согласием.
- Пять ablation-методов, 95% group-bootstrap, отдельные robustness probes и протокол сбора слепого набора. Независимый набор ещё не собран.
- Общий SQL-лимитер и PostgreSQL pool до 5 соединений на процесс; пакет расходует квоту по числу записей. Публичный сервис остаётся одной бесплатной репликой.

## Быстрый запуск

Требуется Python 3.12. Выполняйте команды из корня репозитория.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Откройте **http://localhost:8000**. Локально используется SQLite без дополнительной настройки. Шрифт с кириллицей для PDF включён в репозиторий с лицензией. В Windows активируйте `.venv\Scripts\activate`.

## Docker + PostgreSQL

```bash
cp .env.example .env
# Замените POSTGRES_PASSWORD и пароль в DATABASE_URL; используйте URL-безопасный пароль.
docker compose up --build -d
```

Откройте http://localhost:8000. База не публикует порт наружу. `docker compose down` останавливает сервисы и сохраняет данные в volume.

## Демо за 3 минуты

1. Откройте анализатор, выберите пример «Фишинг», нажмите «Проверить на угрозы».
2. Покажите риск-балл, найденные признаки и рекомендацию. Скачайте PDF.
3. Проверьте «Уведомление», затем «Подмена домена».
4. Откройте «Обзор угроз» и «История проверок»: данные получены из выполненных проверок.
5. Проверьте диалог, переключите РУС / ҚАЗ и выберите ситуацию «Что уже произошло?».
6. «Архив эксперимента» показывает прежние серверные метрики с их ограничениями.

## Проверки и эксперимент

Браузер: `pip install -r tests/requirements.txt`, `python -m playwright install chromium`. При запущенном приложении: `python -m tests.browser_smoke`, `python -m tests.design_browser_smoke`. Проверка аккаунтов с имитацией доставки (без настоящих писем): `python -m tests.auth_browser_smoke`.

```bash
python -m unittest discover -s tests -v
node --test tests/local_analyzer.test.cjs
node --check frontend/app.js
node --check frontend/local-store.js
python -m ai.dataset.generate
python -m ai.evaluate
```

Эти метрики относятся к прежнему серверному эксперименту, не к локальному анализатору. Датасет включён в репозиторий: 132 строки, 44 авторских шаблона RU/KZ/EN. Обучение: 90 строк / 30 шаблонов; тест: 42 строки / 14 шаблонов. Варианты одного шаблона не пересекают границу train/test. Повторения внутри тестовых групп коррелированы.

| Метод | Precision | Recall | F1 | ROC-AUC | FPR |
|---|---:|---:|---:|---:|---:|
| Правила | 1.000 | 1.000 | 1.000 | 1.000 | 0.000 |
| ML baseline | 0.875 | 1.000 | 0.933 | 1.000 | 0.143 |
| Hybrid, приложение | 0.875 | 1.000 | 0.933 | 1.000 | 0.143 |

**Это результат на малом синтетическом наборе, а не реальная точность банковского продукта.** Простые правила превосходят ML в этом эксперименте. Тест использован при разработке; перед заявлениями об обобщении нужен новый внешний слепой набор. Актуальные метрики, hash датасета, latency и ошибки находятся в `ai/evaluation/`.

## Реализация

- Frontend: тёмный адаптивный HTML/CSS/JavaScript без CDN и шага сборки, интерфейс на русском. React оставлен возможным следующим этапом; он не нужен для текущего демо.
- Backend: FastAPI, валидация, лимит тела 64 KiB, rate limit, same-origin записи.
- ML: character TF-IDF (3–5) + Logistic Regression; обучение на фиксированной train-части при старте; безопасная загрузка без pickle.
- Risk Engine: объяснимые признаки текста и структуры URL; риск-балл 0–100, без утверждения о вероятности.
- Storage: SQLite локально; PostgreSQL в Docker и Render. Сохраняются производные признаки и домены, исходные тексты и query strings не сохраняются.
- Session: случайный HttpOnly cookie изолирует истории; это демо-сессия, не банковская аутентификация.
- Reports: предпросмотр и PDF с кириллицей, крупной оценкой риска, признаками, рекомендациями и ограничениями; длинные отчёты автоматически разбиваются на страницы.

Аккаунты дополнительно хранят контакты с согласием; их можно удалить вместе с историей. Страница данных: `/#privacy`. Локализация и обработка у провайдеров требуют проверки до реального пилота.

Ссылки не открываются и не разрешаются через DNS. HTTPS и наличие домена в демонстрационном справочнике не гарантируют безопасность. WHOIS, возраст домена, содержимое страницы, репутационные сервисы и вложения не проверяются. Отрицания распознаются только ограниченной эвристикой.

Для PostgreSQL-развёртывания задайте `REQUIRE_POSTGRES=true`: приложение откажется запускаться с отсутствующей/неверной настройкой вместо незаметного перехода на SQLite. Health endpoint различает подключённую PostgreSQL, локальный SQLite и временное хранилище Render. Проверка истории после реального redeploy: `python -m scripts.verify_persistence record`, затем после deploy — `python -m scripts.verify_persistence verify`. Сначала требуется установить `DATABASE_URL` в Render; подробности — в [инструкции развёртывания](docs/deployment.md).
