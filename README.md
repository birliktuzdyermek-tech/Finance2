# Qalqan Finance Security

Браузерный помощник для проверки финансового фишинга в SMS, WhatsApp, email и URL. Интерфейс RU/KK, локальные правила, точные фрагменты с объяснениями, анализ диалога и практические шаги после подозрительного контакта.

**Текущая браузерная проверка не отправляет сообщения, URL, результаты или выбранные действия на сервер.** История (до 200 результатов) и обзор живут только в памяти вкладки и очищаются при перезагрузке. PDF сохраняется через печать браузера. Старые FastAPI/ML/БД/PDF API сохранены для совместимости, но интерфейс анализа их не вызывает. Только открытие «Архива эксперимента» загружает фиксированные метрики без пользовательских данных.

В диалоге разделяйте реплики пустой строкой: 2–20 реплик, всего до 10 000 символов. Общий балл — сумма весов разных правил по всем репликам, максимум 100; повтор одного правила не увеличивает балл. Это **не вероятность мошенничества** и не подтверждение подлинности отправителя/сайта. Подробнее: [локальная проверка и ограничения](docs/local-assistant.md).

## Быстрый запуск

Требуется Python 3.12. Выполняйте команды из корня репозитория.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Откройте **http://localhost:8000**. Локально используется SQLite без дополнительной настройки. Шрифт с кириллицей для PDF включён в репозиторий с лицензией. В Windows активируйте `.venv\Scripts\activate`.

## Docker + PostgreSQL

```bash
cp .env.example .env
# Замените POSTGRES_PASSWORD и пароль в DATABASE_URL; используйте URL-безопасный пароль.
docker compose up --build -d
```

Откройте http://localhost:8000. База не публикует порт наружу. `docker compose down` останавливает сервисы и сохраняет данные в volume.

## Демо за 3 минуты

1. Откройте анализатор, выберите пример «Фишинг», нажмите «Проверить на угрозы».
2. Покажите риск-балл, подсвеченные фрагменты и причины. «Печать / сохранить PDF» формирует отчёт локально.
3. Проверьте «Уведомление», затем «Подмена домена».
4. Откройте «Обзор угроз» и «История проверок»: данные получены из выполненных проверок.
5. Переключите режим на «Диалог» и вставьте реплики через пустую строку. Проверьте общий результат и каждую реплику.
6. Выберите ситуацию в «Что уже произошло?» и переключите язык RU/KK. «Архив эксперимента» содержит метрики прежней серверной модели, не текущего браузерного анализатора.

## Проверки и эксперимент

```bash
python -m unittest discover -s tests -v
node --test tests/local_analyzer.test.cjs
node --check frontend/app.js
node --check frontend/analyzer.js
node --check frontend/i18n.js
python -m ai.dataset.generate
python -m ai.evaluate
```

Проверка в реальном браузере: `pip install -r tests/requirements.txt`, `python -m playwright install chromium`, затем при запущенном приложении `python -m tests.browser_smoke`. Можно указать `TEST_BASE_URL` и `CHROMIUM_PATH`. Тест проверяет отсутствие передачи данных, работу без сети после загрузки страницы, подсветку, диалог, действия, RU/KK, XSS, историю, печать и мобильную раскладку.

Следующие метрики относятся **только к архивному серверному эксперименту**. Датасет включён в репозиторий: 132 строки, 44 авторских шаблона RU/KZ/EN. Обучение: 90 строк / 30 шаблонов; тест: 42 строки / 14 шаблонов. Варианты одного шаблона не пересекают границу train/test. Повторения внутри тестовых групп коррелированы.

| Метод | Precision | Recall | F1 | ROC-AUC | FPR |
|---|---:|---:|---:|---:|---:|
| Правила | 1.000 | 1.000 | 1.000 | 1.000 | 0.000 |
| ML baseline | 0.875 | 1.000 | 0.933 | 1.000 | 0.143 |
| Hybrid, архивный API | 0.875 | 1.000 | 0.933 | 1.000 | 0.143 |

**Это результат на малом синтетическом наборе, а не реальная точность банковского продукта.** Простые правила превосходят ML в этом эксперименте. Тест использован при разработке; перед заявлениями об обобщении нужен новый внешний слепой набор. Актуальные метрики, hash датасета, latency и ошибки находятся в `ai/evaluation/`.

## Реализация

- Frontend: адаптивный HTML/CSS/JavaScript без CDN и шага сборки; локальный анализ в `frontend/analyzer.js`, RU/KK в `frontend/i18n.js`. Пользовательский текст выводится через текстовые DOM-узлы.
- Backend: FastAPI, валидация, лимит тела 64 KiB, rate limit, same-origin записи.
- ML: character TF-IDF (3–5) + Logistic Regression; обучение на фиксированной train-части при старте; безопасная загрузка без pickle.
- Risk Engine: объяснимые признаки текста и структуры URL; риск-балл 0–100, без утверждения о вероятности.
- Storage: история интерфейса хранится только в памяти вкладки. Отдельные старые API-клиенты по-прежнему используют SQLite/PostgreSQL; их поведение не менялось.
- Session: случайный HttpOnly cookie изолирует истории; это демо-сессия, не банковская аутентификация.
- Reports: локальная печать/PDF браузера. Старый серверный PDF endpoint сохранён для API-клиентов.

Ссылки не открываются и не разрешаются через DNS. HTTPS и наличие домена в демонстрационном справочнике не гарантируют безопасность. WHOIS, возраст домена, содержимое страницы, репутационные сервисы и вложения не проверяются. Отрицания распознаются только ограниченной эвристикой.
